## Slide 1: CoAP - HTTP for Constrained Devices
- Designed for IoT devices with limited memory, CPU, and power
- Protocol optimized for small devices that can't handle full HTTP/TCP stack
- Built on UDP instead of TCP to reduce overhead and complexity
- Enables resource discovery and RESTful interactions in constrained networks
- Maintains HTTP-like semantics while drastically reducing message size

## Slide 2: The Problem with HTTP/TCP in IoT
- TCP requires 3-way handshake for connection establishment
- Full HTTP headers consume significant bandwidth and memory
- Maintaining persistent connections drains battery on constrained devices
- TCP state management too complex for microcontrollers
- HTTP overhead impractical for networks with high packet loss rates

## Slide 3: UDP Foundation and Reliability
- CoAP uses UDP to avoid TCP connection overhead
- Implements custom reliability layer on top of UDP when needed
- CON (confirmable) messages require ACK acknowledgment
- NON (non-confirmable) messages for less critical data with no ACK
- Message IDs and tokens handle deduplication and request-response matching

## Slide 4: RESTful Methods and Response Codes
- Supports GET, POST, PUT, DELETE methods like HTTP
- Uses numeric response codes similar to HTTP (2.05 Content, 4.04 Not Found)
- Binary encoding dramatically reduces message size vs HTTP text
- Request/response model familiar to HTTP developers
- Asynchronous responses through separate CON messages

## Slide 5: Message Format and Binary Encoding
- Fixed 4-byte header with version, type, token length, code, message ID
- Options encoded in TLV (Type-Length-Value) binary format
- Token (0-8 bytes) matches requests to responses across transactions
- Payload follows options with 0xFF marker separator
- Total header size typically 10-20 bytes vs hundreds in HTTP

## Slide 6: Proxy Architecture and Protocol Translation
- Forward proxy translates between CoAP and HTTP
- Reverse proxy exposes CoAP resources via HTTP to internet
- Proxy enables integration with existing HTTP infrastructure
- Caching at proxy layer reduces traffic to constrained devices
- URI mapping between coap:// and http:// schemes

## Slide 7: Multicast and Group Communication
- Supports multicast requests to discover resources
- Special multicast addresses (ALL CoAP Nodes) for service discovery
- NON messages for multicast to avoid ACK implosion
- Multiple devices can respond to single multicast query
- Efficient way to locate services in local network without central directory

## Slide 8: Resource Discovery and .well-known/core
- Standard endpoint /.well-known/core lists available resources
- Returns CoRE Link Format describing resources and attributes
- Clients discover capabilities without prior knowledge
- Resource Type (rt), Interface (if), Content-Type (ct) attributes
- Supports filtered queries to find specific resource types

## Slide 9: Observe Extension for Pub-Sub
- Client registers interest in resource with Observe option
- Server sends notifications when resource state changes
- Eliminates need for client polling in monitoring scenarios
- Notifications use same token as original registration
- Client can cancel observation or server can terminate

## Slide 10: Security with DTLS
- DTLS (Datagram TLS) provides encryption and authentication over UDP
- Supports pre-shared keys, raw public keys, and certificates
- Equivalent security to HTTPS with TLS
- Adds overhead but essential for sensitive IoT deployments
- Careful consideration of DTLS handshake cost on constrained devices
