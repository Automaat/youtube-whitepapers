## Slide 1: HTTP/3 Introduction - Evolution Beyond TCP
- HTTP/3 (RFC 9114) represents fundamental shift in web protocol architecture
- Built on QUIC transport protocol instead of traditional TCP
- QUIC runs over UDP, providing stream multiplexing at transport layer
- Designed to eliminate head-of-line blocking inherent in HTTP/2 over TCP
- Maintains HTTP semantics while completely reimagining underlying transport

## Slide 2: The TCP Head-of-Line Blocking Problem
- HTTP/2 multiplexes multiple streams over single TCP connection
- TCP ensures ordered byte delivery across entire connection
- Single lost packet blocks all streams, even unaffected ones
- Network congestion or packet loss degrades all concurrent requests
- Problem particularly severe on high-latency or lossy networks

## Slide 3: QUIC as Foundation - UDP-Based Transport
- QUIC provides reliable, connection-oriented transport over UDP
- Implements independent streams with per-stream flow control
- Combines transport and encryption (TLS 1.3) into single handshake
- Native support for connection migration across network changes
- Eliminates TCP's sequential delivery constraint at transport layer

## Slide 4: Independent Stream Reliability
- Each QUIC stream has independent reliability and ordering guarantees
- Lost packets only block affected stream, not entire connection
- Streams can be unidirectional or bidirectional as needed
- Per-stream flow control prevents single stream monopolizing bandwidth
- Dramatically improves performance under packet loss conditions

## Slide 5: Bidirectional and Unidirectional Streams
- Bidirectional streams allow request/response communication patterns
- Unidirectional streams support server push and specialized data flows
- Stream IDs encode directionality and initiator (client vs server)
- Dynamic stream creation without coordination overhead
- Efficient resource utilization through appropriate stream type selection

## Slide 6: HTTP/2 Server Push Challenges
- HTTP/2 server push often inefficient due to cache unawareness
- Servers push resources client may already have cached
- No effective mechanism for client to signal cached resources before push
- Bandwidth wasted on duplicate transfers
- Adoption remained low despite theoretical benefits

## Slide 7: Connection Migration and 0-RTT
- QUIC supports connection migration via connection IDs
- Mobile devices maintain connection when switching networks (WiFi to cellular)
- 0-RTT resumption enables immediate data transmission on reconnection
- Reduces latency for repeat connections significantly
- Critical for mobile-first web experience

## Slide 8: HTTP/3 Frame Structure and Mapping
- HTTP/3 frames map to QUIC streams, not TCP byte stream
- HEADERS, DATA, and SETTINGS frames core to protocol operation
- QPACK header compression replaces HPACK from HTTP/2
- Frame boundaries align with stream semantics
- Simplified priority signaling compared to HTTP/2

## Slide 9: QPACK Header Compression
- QPACK designed for out-of-order stream delivery unlike HPACK
- Dynamic table updates sent on dedicated unidirectional stream
- Decoders can process headers without blocking on table updates
- Provides compression efficiency while avoiding head-of-line blocking
- Trade-off between compression ratio and decoding independence

## Slide 10: Migration Challenges and Deployment
- UDP often blocked or rate-limited by middleboxes and firewalls
- Requires fallback to HTTP/2 or HTTP/1.1 when QUIC unavailable
- Server and client implementation complexity significantly higher
- Performance gains require careful tuning and optimization
- Gradual adoption by major platforms (Google, Cloudflare, Facebook)
