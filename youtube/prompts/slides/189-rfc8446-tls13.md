## Slide 1: TLS 1.3 - Revolution Not Evolution
- Official specification for Transport Layer Security version 1.3 (RFC 8446)
- The small padlock icon in browser address bars protecting digital life
- TLS 1.2 served for over a decade (since 2008) but internet changed dramatically
- New sophisticated attacks emerged requiring fundamental security redesign
- Complete overhaul of protocol foundations instead of incremental patches

## Slide 2: Cryptographic Algorithm Cleanup
- Removed entire legacy cipher suites and weak symmetric ciphers
- Only modern AEAD (Authenticated Encryption with Associated Data) modes retained
- AEAD combines encryption and authentication in single secure operation
- Eliminated separate encryption/authentication steps reducing attack surface
- Minimalism approach: fewer options means fewer implementation mistakes

## Slide 3: Forward Secrecy Becomes Mandatory
- Completely removed static key exchange modes (static RSA, static Diffie-Hellman)
- Forward secrecy now mandatory default for all sessions, not optional
- Each session uses ephemeral (temporary) keys that are destroyed after use
- If long-term server key compromised, past traffic remains protected
- Future-proof security: recorded encrypted traffic stays secure forever

## Slide 4: Additional Security Removals
- Compression removed due to vulnerability to attacks like CRIME
- Legacy signature algorithm DSA eliminated from protocol
- Philosophy: "less means better" - aggressive reduction of attack vectors
- Every removed feature is potential vulnerability eliminated
- Simplified codebase easier to audit and implement correctly

## Slide 5: Handshake Protocol Redesign - 1-RTT
- TLS 1.2 required two full round trips (2-RTT) for handshake completion
- TLS 1.3 compressed to single round trip (1-RTT) in each direction
- Client sends message and can immediately start transmitting encrypted data
- Dramatically faster page loading especially on mobile/slow connections
- Network latency impact reduced by 50% for connection establishment

## Slide 6: Encrypted Handshake for Privacy
- TLS 1.2 transmitted large portions of negotiation in plaintext including server certificate
- Anyone on same WiFi network could see which servers you connect to
- TLS 1.3 encrypts almost entire handshake except initial ClientHello/ServerHello
- Server certificate and most negotiation parameters now hidden from observers
- Enhanced metadata privacy protecting connection patterns from surveillance

## Slide 7: Zero-RTT Mode - Speed with Tradeoffs
- Uses PSK (Pre-Shared Key) mechanism from previous session as "ticket"
- Client can encrypt and send early data immediately with zero round trips
- Connection time reduced to practically zero for returning visitors
- CRITICAL LIMITATION: Zero-RTT data lacks forward secrecy
- Vulnerable to replay attacks - attacker can resend captured packets multiple times

## Slide 8: Zero-RTT Replay Attack Risks
- Attacker intercepts first Zero-RTT packet and retransmits it repeatedly
- Server may process each copy as legitimate new request without full context
- Example: "buy one concert ticket" request could result in purchasing 10 tickets
- RFC explicitly restricts Zero-RTT to idempotent operations only
- Safe use cases: search queries, GET requests - operations safe to repeat

## Slide 9: Key Derivation with HKDF
- Separate keys protect handshake phase versus application data phase
- HKDF (HMAC-based Key Derivation Function) generates all session keys
- Keys derived by mixing secret with TranscriptHash (cryptographic hash of conversation)
- Each session produces unique TranscriptHash from random values exchanged
- Simple but powerful concept ensuring keys isolated between sessions

## Slide 10: Design Philosophy - Strength Through Simplicity
- Not incremental update but fundamental protocol redesign
- Radically simplified making implementation errors more difficult
- Noticeably faster connection establishment and page loads
- Demonstrably more secure with forward secrecy as hard requirement
- Success of pragmatic approach: strengthening by removing problematic features
