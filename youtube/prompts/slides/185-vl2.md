## Slide 1: Introduction to VL2 Architecture
- VL2 addresses fundamental limitations of traditional data center networks
- Designed for large-scale cloud computing environments with unpredictable traffic patterns
- Provides uniform high bandwidth between any pair of servers
- Enables virtual machine mobility without IP address changes
- Built on commodity switching hardware for cost efficiency

## Slide 2: Problems with Traditional Tree Networks
- Conventional tree topology creates bandwidth bottlenecks at higher layers
- Over-subscription ratio (paying for 2 links but using only 1)
- Traffic patterns in cloud DCs are unpredictable and dynamic
- VM placement constraints due to network topology
- Poor utilization of available network capacity

## Slide 3: VL2 Core Design Goals
- Uniform high bandwidth: any server to any server communication at full rate
- Performance agnostic to server location in network topology
- Support for virtual machine mobility across the entire data center
- Enable flexible resource pooling for improved utilization
- Build on commodity Ethernet switches to control costs

## Slide 4: Clos Network Topology
- Three-layer fat-tree structure: ToR (Top-of-Rack), aggregate, and intermediate layers
- Each ToR switch connects upward to multiple aggregate switches
- Aggregate switches connect to intermediate layer switches
- Creates multiple equal-cost paths between any pair of servers
- Provides full bisection bandwidth across the network

## Slide 5: Server Address Virtualization
- Separation of application addresses (AA) from location addresses (LA)
- Application addresses remain constant during VM migration
- Location addresses identify physical network position
- Directory system maps AA to LA dynamically
- Servers maintain their IP addresses regardless of physical location

## Slide 6: Valiant Load Balancing
- Traffic deliberately routed through random intermediate switches first
- Spreads load evenly across all available paths
- Prevents hot-spots and ensures balanced utilization
- Two-phase routing: ToR → random intermediate → destination ToR
- Achieves near-optimal traffic distribution without centralized coordination

## Slide 7: VL2 Routing and Forwarding
- IP-in-IP encapsulation for routing packets
- ToR switches encapsulate packets with LA headers
- Intermediate switches route based on LA only
- Destination ToR switch decapsulates and delivers to final AA
- Standard IP routing protocols work without modification

## Slide 8: Directory System Design
- Centralized directory service maps application addresses to location addresses
- ToR switches query directory for AA-to-LA mappings
- Caching at ToR level reduces directory lookup overhead
- Reactive cache updates on first packet of each flow
- Scalable design handles millions of address mappings

## Slide 9: Performance and Implementation
- Deployed in Microsoft data centers serving real production workloads
- Achieves near-theoretical maximum bisection bandwidth
- Handles traffic patterns that would cripple traditional tree networks
- Commodity switches reduce capital expenditure significantly
- Proven scalability to thousands of servers

## Slide 10: Impact on Data Center Design
- Decouples application placement from network topology constraints
- Enables more efficient server utilization through flexible VM placement
- Simplifies network management and capacity planning
- Influenced subsequent data center network architectures
- Established principles for modern cloud infrastructure networking
