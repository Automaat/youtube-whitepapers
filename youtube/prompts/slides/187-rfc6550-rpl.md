## Slide 1: Introduction to RPL - IoT Routing Protocol
- Designed for Low-Power and Lossy Networks (LLNs)
- Operates in unstable environments with frequent link failures
- Optimized for resource-constrained devices (sensors, embedded systems)
- IETF standard for IPv6 routing in IoT networks
- Fundamental protocol for smart home, industrial monitoring, and sensor networks

## Slide 2: LLN Characteristics and Challenges
- Low-Power devices with limited battery life and processing capacity
- Lossy communication links with high packet loss rates
- Unstable network topology with frequent node failures
- Asymmetric links (different quality in each direction)
- Requires adaptive routing to maintain connectivity in harsh conditions

## Slide 3: DODAG - Directed Acyclic Graph Structure
- Destination-Oriented DAG: tree structure rooted at border router
- Acyclic: no routing loops by design
- Directed: traffic flows toward root (upward) and toward leaves (downward)
- Each node selects preferred parent based on Objective Function
- Multiple DODAGs can coexist in same network

## Slide 4: Node Roles and Power Classes
- Root node: border router connecting LLN to external networks
- Router nodes: forward traffic, participate in route maintenance
- Leaf nodes: endpoints that only send/receive data
- Mains-powered nodes: stable routers with constant power supply
- Battery-powered nodes: energy-constrained, minimize transmission overhead

## Slide 5: DIO - Building Upward Routes
- DODAG Information Object: broadcast message for topology discovery
- Advertises DODAG rank, Objective Function, and network parameters
- Nodes receive DIO from neighbors, select preferred parent
- Propagates downward from root to build upward routing paths
- Suppressed by Trickle algorithm to reduce control overhead

## Slide 6: Trickle Algorithm - Adaptive Control Traffic
- Exponentially backs off DIO transmission when network is stable
- Rapidly increases frequency when topology changes detected
- Listens to neighbor DIOs: if consistent, extends quiet period
- Detects inconsistencies (version number mismatch) and resets timer
- Dramatically reduces energy consumption in stable networks

## Slide 7: DAO - Building Downward Routes
- Destination Advertisement Object: advertises reachable destinations
- Nodes send DAO upward to root with list of child nodes
- Builds routing table for downward traffic (root to leaves)
- Two modes: storing (routers maintain routing tables) and non-storing (source routing from root)
- Critical for point-to-multipoint communication patterns

## Slide 8: DIS - Route Discovery and Repair
- DODAG Information Solicitation: requests DIO from neighbors
- Used by new nodes joining network or after parent failure
- Triggers immediate DIO response (bypasses Trickle suppression)
- Enables faster topology recovery after link failures
- Helps nodes quickly find alternative parents

## Slide 9: Objective Functions - Route Optimization
- OF defines routing metric and parent selection algorithm
- OF0 (Zero): uses hop count as primary metric
- MRHOF (Minimum Rank with Hysteresis): uses ETX, energy, latency metrics
- Allows network operators to optimize for different goals (reliability vs energy)
- Different DODAGs can use different OFs for application-specific routing

## Slide 10: Security Mechanisms and Attack Mitigation
- Rank attack: malicious node advertises artificially low rank to attract traffic
- Version number attack: attacker triggers global network reset
- Authentication using pre-shared keys or digital signatures
- Rank consistency checks to detect suspicious topology changes
- Best practice: deploy RPL in controlled, semi-trusted environments
